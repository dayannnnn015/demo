# Standing rules, gates and settled decisions

This is the single source of truth for what EDUNEXUS may not do, what it cannot do yet, and what has already been decided. Read it before [the roadmap](roadmap.md): where the two disagree, this file wins and the roadmap is wrong and should be corrected.

It exists because "not built yet" and "must never be built" are different statements that read alike in a requirements list. A rule below is permanent. A gate is a thing that is blocked, by a named decision, held by a named party. Anything in neither table is ordinary work.

## Standing rules

Never violate these. Changing one takes an explicit written instruction, recorded in the table.

| Rule | Why | Changed by |
|---|---|---|
| Teachers read only the learners in the classes they advise. Changing a learner record is a manager's — **with three exceptions**, each decided and each narrow: the adviser's historical encoding (2026-11-03), taking an already-registered learner into a class they advise, and registering a new learner into it (both 2026-11-05) | The manuscript's two statements conflicted and the user chose manager-only; the three exceptions were asked for afterwards and are recorded in the decisions table with their dates and their limits. **The read scope never widened** — row security is untouched — and no profile correction, LRN, grade change or withdrawal is open to a teacher | User instruction, then three revised workflows |
| **Nothing computes a grade** — no total, average, percentage, MPS, GWA or transmutation, anywhere, including client-side in the UI | Grades on the forms are the ones advisers enter from the DepEd ECR (2026-10-08). The arithmetic is DepEd's, not ours, and a wrong rule silently corrupts real report cards | Nothing. This is no longer merely gated: calculation was superseded by entry |
| Do not invent official grading rules, weights, transmutation, rounding, a passing mark or numeric Kindergarten grading | EDUNEXUS is not the authority on DepEd policy | The school supplying the rule, via the grading gate below |
| **Absence of a record is not evidence.** An unmarked attendance session and an unrecorded score are `null`, never zero and never "present" | Several modules exist specifically to preserve this; so does `Unrecorded` in the interface | Nothing |
| **Attendance figures come only from the school's recorded rule**, computed in `src/modules/forms/attendance.ts` and nowhere else. With no rule, an unmarked session, an unset date or an alternative-delivery date, the figure is **empty, never estimated** | An estimated attendance figure on an official return is a fabricated record | Nothing |
| **The SF10 is one cumulative record per learner, derived on every read, and it begins at Grade 1** | It is never a stored document, there is no per-year SF10, and Kindergarten is the credential presented for Grade 1 rather than a scholastic block (2026-11-03, 2026-11-04) | Nothing short of a DepEd form change |
| **Every SF4 figure is counted by section**, and a registered learner with no class is reported on their own, never folded into a rollup | A grade subtotal must equal the rows printed above it (0052, 2026-11-04) | Nothing |
| Never weaken database permissions, version checks or audit history to make a workflow easier | These are the correctness and privacy boundary, not an implementation detail | Nothing short of a redesign |
| Never modify an already-applied migration; add a new one | Applied migrations are checksummed and the runner refuses a modified file | Nothing |
| Never commit or expose credentials from `.env` or `.local` | Real school deployment secrets | Nothing |
| Use synthetic data in tests, and roll back hosted test fixtures | Real learner data is sensitive personal information under the Data Privacy Act | Nothing |
| The manuscript stays in its original location and is never committed | It is source material, not a repository artifact | Nothing |
| Do not weaken backend controls so a frontend workflow is easier to build | The API is the authority; the UI is a convenience over it | Nothing |
| **Never run `supabase config push`** | The pull deliberately skipped settings it could not represent, so a push would write local defaults over them, including disabling Twilio | Nothing |

## Gates

Each of these is blocked on information EDUNEXUS cannot derive. Do not build past one. Do not approximate it with a default.

| Gate | What it blocks | Who decides | Opened by |
|---|---|---|---|

| **Subject-teacher access** | Three teachers recording anything for the classes they actually teach but do not advise | School | **Raised 2026-11-04; integration deferred 2026-11-05 because the role itself is unconfirmed, so this gate now has a prior question: does the school run this role officially, and what is it called?** The school's own SF4 shows three teachers teaching across sections they hold no advisory for (Science and MAPEH in Grade 4; Araling Panlipunan with GMRC and with MAPEH across Grades 5 and 6). The school has confirmed it has none — but its own SF2 obliges the adviser to intervene at five consecutive absences and counts those learners monthly. **Contested since 2026-09-19**; the gate stays shut until the school says which is current. Follow-up stays manual and nothing alerts, messages or notifies |

Observed sizes are known since 2026-09-19 — 18–20 in Kinder, 29–37 elsewhere — and observation is not policy. Next year's classes enforces and suggests no maximum, deliberately. **One field left this gate on 2026-11-04**, by the user's explicit decision: `learners.address`, one nullable line, needed for the initial learner-information import (0053). It stays shut for every other field — mother tongue, religion, indigenous group, parent or guardian, contact number, or any breakdown of that line into columns — and the reviewed field list is still what opens it |
| **Load and recovery verification** | Section 7 turnover | Operator, with targets agreed with the school | 27+ concurrent *hosted* session testing, backup restoration into an isolated project, privilege revocation and rollback drills. `npm run test:race` and `npm run test:load` pass locally; hosted throughput, realistic multi-session authentication load and every concurrent locking race are **not** established |

School acceptance is still outstanding |
| **Service-role key in the runtime** | Nothing currently built. ## Using this file

When planning an increment, check the gates first. If the work sits behind a closed gate, it is blocked: say which gate and stop, rather than approximating the missing decision. Every step in [the roadmap](roadmap.md) names the gate it depends on, or states **Gate: none**.

When the user's instructions and this file disagree, ask before building. That ambiguity is what this file exists to remove, and a wrong guess is expensive in a system that will hold real learner records.
